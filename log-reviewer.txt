```javascript
// 当前代码
this._fullCode = ''; this._fullText = '';

// 应改为（与 reset() 保持一致）
this._fullCode = ''; this._fullText = ''; this._fullDecode = '';
```

### 发现 1 个运行时 bug：`loadHistory` 不更新 `_imageCache`，导致转换新图片后数据错位

**位置：** `loadHistory`（index.js:1784-1809）

**问题：** `loadHistory` 调用 `reset('img2code')` 或 `reset('text2code')` 切换模式，但 `reset()` 不清空 `_imageCache`（这是正确的，防止切换模式丢失数据）。然后 `loadHistory` 设置 `images` 为单个历史项，但 `_imageCache` 仍保留项目所有项的数据。

**触发场景：**
1. 用户打开一个有 5 张图片的项目 → `_imageCache` = 5 项，`images` = 5 项
2. 点击第 3 张图片的"加载" → `reset('img2code')` 清空显示，`_imageCache` 仍为 5 项
3. `images` 被设为第 3 张图片（1 项），但 `_imageCache` 仍为 5 项 → **索引错位**
4. 用户选择一张新图片并转换 → `_doReadBase64` prepend 新项到 `_imageCache`（6项）和 `images`（2项）
5. 此时 `images[1]`（新图片）映射到 `_imageCache[1]`（旧项目第 2 张图片的 base64）→ **数据错位**
6. `saveImages` 保存时，新图片的 base64 字段被写入旧图片的数据

**影响：** 用户加载历史项后转换新图片，新图片的 base64 数据会被旧图片数据覆盖。属于低频场景，但一旦触发会导致数据丢失。

**修复方案：** `loadHistory` 在 `reset()` 后重新从项目数据初始化 `_imageCache`，与 `openProject`/`onShow` 保持一致：

```javascript
// loadHistory 函数中，reset() 之后添加：
let ps = this._getPs();
let proj = ps.find(x => x.id === this.data.curId);
if (proj) {
  this._imageCache = (proj.items || []).map(item => ({ base64: item.base64 || '', textContent: item.textContent || '' }));
}
```
