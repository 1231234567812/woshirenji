**第三十四轮审查 — 发现 1 个运行时 bug + 1 个代码优化机会**

### Bug 1（中等）：`_saveTempImage` 缺少 null 检查

**位置：** `index.js:1506-1508`

```javascript
_saveTempImage(tempPath) {
    this._saveToTempFile(tempPath, 'img', (dest) => this._onImagePicked(dest));
},
```

**问题：** `_saveToTempFile` 在双失败时会调用 `callback(null)`（第1500行）。`_saveTempImage` 没有检查 `dest` 是否为 null，直接传给 `_onImagePicked(null)`，导致 `imagePath` 被设为 null。

**对比：** 其他 8 个 choose 函数全部有 null 检查：
- `chooseCompressImage`（679行）：`if (p) that._onCompressImagePicked(p)`
- `chooseWmImage`（791行）：`if (p) that.setData(...)`
- `chooseFmtImg`（964行）：`if (!dest) return`
- `chooseResizeImg`（1022行）：`if (!dest) return`
- `chooseCropImg`（1103行）：`if (!dest) return`
- `chooseRotImg`（1196行）：`if (!dest) return`
- `chooseColorImg`（1319行）：`if (!dest) return`
- `chooseMosaicImg`（1414行）：`if (!dest) return`

**唯一遗漏的就是 `_saveTempImage`。**

**影响：** 图片保存失败时，`imagePath` 为 null，后续 `convertImage()` 检查 `if (!src) return` 会静默失败，用户不知道发生了什么。

**修复方案：**
```javascript
_saveTempImage(tempPath) {
    this._saveToTempFile(tempPath, 'img', (dest) => { if (dest) this._onImagePicked(dest); });
},
```

### Bug 2（低）：`Date.now()` 生成的 ID 可能重复

`generateQR`（448行）、`_doReadBase64`（1590行）、`_batchConvertOne`（356行）等多处使用 `Date.now()` 作为 `itemMeta.id`。如果用户在 1ms 内连续操作（如快速点击批量转换），生成的 ID 会重复，导致 `wx:key` 警告和列表渲染异常。

**影响：** 低概率，但快速操作时可能出现。

**建议：** 使用 `Date.now() + '_' + Math.random().toString(36).slice(2, 8)` 或递增计数器。

### 代码优化机会（非 bug）

`doRotate`（1207-1300行，~90行）手动实现了 canvas 绘制+导出逻辑，与 `_canvasProcess` 功能完全重叠。改用 `_canvasProcess` 可减少 ~60 行代码。`_canvasExport`（120-160行）也与 `_canvasProcess` 高度重叠，可考虑合并。
